Great question! Let me explain the complete data flow from generation to visualization in the Grafana dashboard:

📊 Data Flow to Grafana Dashboard
mermaid
graph LR
    A[Telemetry API] -->|1. Generate| B[Metrics in Memory]
    B -->|2. Expose| C[/metrics endpoint]
    C -->|3. Scrape every 5s| D[Prometheus]
    D -->|4. Store| E[Time-Series DB]
    E -->|5. Query| F[Grafana]
    F -->|6. Display| G[Dashboard]
Step-by-Step Process
Step 1: Telemetry API Generates Metrics (Every 5 seconds)
The 
telemetry_api.py
 has a background task that runs continuously:

python
# Runs every 5 seconds
async def generate_metrics_task():
    while True:
        # Generate random metrics for 3 routers
        Router-1: CPU=73.88%, Latency=86.12ms, PacketLoss=0.37%
        Router-2: CPU=87.63%, Latency=14.24ms, PacketLoss=0.86%
        Router-3: CPU=81.56%, Latency=62.13ms, PacketLoss=3.28%
        
        await asyncio.sleep(5)  # Wait 5 seconds
Step 2: Metrics Exposed at /metrics Endpoint
The API exposes metrics in Prometheus format at http://localhost:8000/metrics:

bash
curl http://localhost:8000/metrics
Output:

# HELP device_cpu_usage CPU usage percentage
# TYPE device_cpu_usage gauge
device_cpu_usage{device="Router-1"} 73.88
device_cpu_usage{device="Router-2"} 87.63
device_cpu_usage{device="Router-3"} 81.56

# HELP device_latency_ms Network latency in milliseconds
# TYPE device_latency_ms gauge
device_latency_ms{device="Router-1"} 86.12
device_latency_ms{device="Router-2"} 14.24
device_latency_ms{device="Router-3"} 62.13

# HELP device_packet_loss Packet loss percentage
# TYPE device_packet_loss gauge
device_packet_loss{device="Router-1"} 0.37
device_packet_loss{device="Router-2"} 0.86
device_packet_loss{device="Router-3"} 3.28
Step 3: Prometheus Scrapes the Endpoint (Every 5 seconds)
Prometheus is configured in 
prometheus.yml
 to scrape the API:

yaml
scrape_configs:
  - job_name: 'telemetry-api'
    scrape_interval: 5s  # Scrape every 5 seconds
    static_configs:
      - targets: ['telemetry-api:8000']
    metrics_path: '/metrics'
What happens:

Every 5 seconds, Prometheus sends: GET http://telemetry-api:8000/metrics
Prometheus parses the response
Stores data points with timestamps
Step 4: Prometheus Stores in Time-Series Database
Prometheus stores each metric with:

Metric name: device_cpu_usage
Labels: {device="Router-1"}
Value: 73.88
Timestamp: 2025-10-13T15:50:28Z
This creates a time-series:

device_cpu_usage{device="Router-1"} @ 15:50:23 = 94.78
device_cpu_usage{device="Router-1"} @ 15:50:28 = 87.66
device_cpu_usage{device="Router-1"} @ 15:50:33 = 73.88
...
Step 5: Grafana Queries Prometheus
Grafana dashboard is configured to query Prometheus every 5 seconds:

Dashboard Configuration (telemetry-dashboard.json):

json
{
  "refresh": "5s",  // Auto-refresh every 5 seconds
  "datasource": "Prometheus",
  "targets": [
    {
      "expr": "device_cpu_usage"  // PromQL query
    }
  ]
}
What Grafana does:

Sends PromQL query to Prometheus: device_cpu_usage
Prometheus returns time-series data
Grafana receives data points for all devices
Updates the graph
Step 6: Dashboard Displays Data
The dashboard shows:

Time-series graphs: Lines showing metrics over time
Auto-refresh: Updates every 5 seconds
Multiple series: One line per device (Router-1, Router-2, Router-3)

... repeats every 5 seconds
